## Usage Contract

- Use canonical terms in plans, interfaces, schemas, tests, and user-facing
  copy when the project language requires them.
- Record aliases for migration and search; do not silently give two meanings
  to one term.
- When source behavior and stakeholder language conflict, mark the entry
  `UNRESOLVED` with an owner and next action.
- Update this file only for reusable project vocabulary, not task-local names.
